# 三国狼人杀

> 从 219 位三国豪杰中随机选拔 9 人或 15 人，进行狼人杀智谋对决。纯前端，浏览器打开即玩。

👉 **[在线试玩](https://ljq695543881.github.io/three-kingdoms-agent/werewolf.html)**

## 快速开始

**零依赖，打开即玩：**

```bash
# 克隆仓库
git clone https://github.com/ljq695543881/three-kingdoms-agent.git
cd three-kingdoms-agent

# 用浏览器打开
open werewolf.html        # macOS
# 或直接双击 werewolf.html
```

仅 `werewolf.html` + `characters_data.js` + `avatars/` 即可运行，无需任何服务器或构建工具。

## 手机与无障碍体验

- 手机端豪杰列表采用五列布局，减少查看战局前的滚动距离。
- 工具栏、属性加减和主要操作提供至少 44px 的触控高度。
- 角色创建、发言、投票与设置等面板限制在可用视口内，内容过长时可滚动。
- 适配动态视口与刘海屏安全区；输入框使用 16px 字体，减少手机输入时的自动放大。
- 支持键盘焦点提示，并尊重系统“减少动态效果”设置。

## 玩法更新

- **选择局型**：首页可选 9 人短局（默认）或 15 人经典局，玩家、天意、上帝三种视角均适用。
- **9 人短局**：2 狼、预言家 / 女巫 / 猎人 / 守卫各 1 人、3 平民；15 人局维持原配置。短局属于新配置，仍需真人试玩调整平衡。
- **发言回应**：玩家发言后，按真实发生的好感度变化展示至多三位角色的反应；不展示精确数值或隐藏身份。支持与质疑并存时会分别展示。
- **信息边界**：玩家存活时，好感度入口仅回看最近三次发言回应；上帝视角保留完整矩阵。
- **结算复盘**：展示每日死亡、首轮 / 重投结果、关键票的投票者、玩家投狼票数及发言回应。身份仅在结算时完整展示，态度不作为投票的因果解释。
- **决策面板可收起**：发言、夜晚行动和投票面板提供“收起面板”和“查看发言历史”；底部“返回… · 尚未提交”可恢复操作，保留片段和目标，不自动提交。
- **奖励保护**：同一局重复触发结算不会重复发放奖励。

## 游戏说明

- **玩法**：可选 9 人短局（2 狼）或 15 人经典局（4 狼）；两种局型均包含四种神职。
- **角色**：每局从 219 位三国人物中按局型随机抽取 9 或 15 人，角色随机分配
- **视角**：上帝视角，观看 AI 自动推演发言、投票、夜间行动
- **交互**：暂停/继续按钮控制游戏节奏

## 玩法回归检查

`tests/gameplay-smoke.cjs` 使用 Playwright 在真实浏览器中跑完短局和经典局，并检查发言反馈、复盘和响应式布局。需预先安装 Playwright 及其 Chromium 浏览器，然后在仓库根目录运行 `node tests/gameplay-smoke.cjs`。可通过 `CHROME_EXECUTABLE` 指定本机 Chrome，或通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径。默认每种局型运行 8 个固定随机种子；`SMOKE_SEEDS` 可调整场次数。

`node tests/panel-collapse.cjs` 检查三种决策面板在手机与桌面上的历史查阅、选择保留、等待确认和重开清理。浏览器依赖与玩法回归检查相同。

## 操作体验与防误触

- 所有回合决策（含猎人和天意）均可收起或查看历史，恢复后保留选择；操作栏保持可见。
- 天意帮助、干扰和静观其变均需显式确认；投票、夜间行动和猎人确认按钮显示选中的目标。
- 重开、返回标题和放弃猎人技能先确认，取消不会丢失当前对局。
- 历史支持展开查看完整原话；查看历史、设置、回应时暂停推演，关闭单个阅读面板不会解除其他面板或手动暂停。
- 阅读旧日志时新消息不抢滚动位置，可点击“查看最新”恢复跟随。
- 支持 Esc 关闭阅读或收起决策面板；Tab 在当前弹窗中移动，人物选择支持 Enter / 空格。创建角色可返回模式选择并保留填写内容。
- 返回标题及重开会取消旧回合继续执行，避免旧对局弹窗重新出现。

`node tests/usability.cjs` 覆盖以上关键操作；浏览器依赖与其他回归脚本相同。

## 生涯与成就

- **18 枚徽章**：保留原有八项，新增首局、首胜、3 / 10 / 50 局、5 胜、3 / 6 身份、双局型和首次准确放逐票等目标。
- **追踪目标**：展示最多三个接近完成的目标，可固定一个到首页；徽章进度和已收集数量直接可见。
- **行军篇章**：完成三场玩家 / 天意对局，并赢得一场，自动获得 40 声望后开启下一篇。不设日期、连续登录或失败清零，输局也计入篇章局数。
- **身份图鉴与五种称号**：记录六类身份的体验次数，解锁可佩戴的展示称号，不增加战斗属性。图鉴从本次更新后开始记录。
- **本局成长**：结算列出新徽章、新称号、推进的目标、篇章进度和下局目标。
- **奖励与迁移**：徽章仅首次达成发奖；重复结算不发奖，篇章可重复完成。旧成就 / 声望 / 局数 / 投票进度保留。准确放逐票以决定放逐的那轮为准，每天最多一次，之后新增的准确票仅统计好人投狼；既有数值不回退。
- **统计范围**：玩家和天意结算计入，上帝观战不计生涯；天意角色阵亡仍计历练，明确失败时不计胜场。所有进度保存在当前浏览器的 localStorage。

`node tests/achievements.cjs` 验证奖励、篇章、称号、图鉴、迁移与手机交互，使用与其他浏览器测试相同的环境变量。

## 发布前边界回归

- 同名人物使用独立玩家座位，不再通过名称查找控制角色。
- 天意新局重新选择附体，0号座位按实际身份过滤私有日志。
- 玩家猎人阵亡后先完成开枪或放弃决策，再进入上帝视角，防止提前查看隐藏身份与夜间私聊。
- 角色名校验与旧角色名规范化避免引号、HTML符号破坏页面；异常声望数据回退为0。
- `node tests/release-boundaries.cjs` 检查以上边界，`node tests/player-flows.cjs` 跑完六种玩家身份和两个天意座位的真实决策流程。

## 夜间技能状态修正

- 女巫面板分别展示实际库存与当晚使用条件：首夜禁毒、不可自救、无救人目标不会扣药，也不会显示“已用完”。首夜仍有解药1瓶、毒药1瓶；每晚最多使用一种。
- 玩家与AI共用同一套女巫可用条件；非法目标不能被选中，按兵不动保留剩余库存。
- 用药与守护的0号座位记录不再遗漏。AI守卫不会连续守同一人。
- 同时受到狼刀和毒药的猎人按毒杀处理，不能开枪；重开后旧夜晚计时器不会影响新局。
- `node tests/night-skills.cjs` 覆盖24种库存 / 夜晚 / 受袭组合、药品消耗、AI规则、夜晚结算和手机展示。
